# 硅基流动推荐排序

实现日期：2026-09-17。导师推荐、学生候选与学习资源推荐已接入同一排序服务。算法版本为 `siliconflow-hybrid-v2`。

## 配置与启动

在后端 `.env` 设置 `SILICONFLOW_API_KEY`，其余参数可沿用 `.env.example` 默认值。已选择的模型为 `BAAI/bge-m3` 与 `BAAI/bge-reranker-v2-m3`，不自动切换到付费 `Pro/` 模型。模型名及官方 API 域名均有限制，配置错误会降级或在配置校验时报告。

```sh
docker compose up --build -d
docker compose exec api alembic current
docker compose exec api python -m app.ranking_smoke --live
```

最后一个命令会显式调用外部服务，只使用代码内置的合成学术文本和内存数据库，不读取用户画像，不写入业务库。普通 pytest 不调用真实 API。

迁移 `20260917_0015` 创建 pgvector 扩展及两张缓存表。数据库账号需要有创建扩展的权限，或由运维预先安装 vector 扩展。Compose 使用的 pgvector 镜像已支持该扩展。升级保留原有数据库和资源文件。

## 排序行为

1. 导师／学生在数据库查询时限定租户、院校标识、角色、激活状态和已完成的候选画像；资源限定租户及已发布状态。未知院校不与另一未知院校互相匹配。
2. 先按本地标签分数选取最多 `RANKING_CANDIDATE_LIMIT=200` 个候选，用 BGE-M3 生成／复用 1024 维向量，再在 PostgreSQL 中计算余弦相关性。
3. 候选按语义分数排序，分批调用 Rerank；`RANKING_RERANK_LIMIT=40` 是每批文档数。进入候选池的所有项目都会重排，部分批次失败时整次回退到一致的向量分数。
4. 默认最终分数为 `80 × rerank + 15 × 非负余弦相关性 + 0.05 × 本地分数`。所有分数均为 0–100。同学院只在同分时优先，最终用用户／资源 UUID 确定稳定顺序。
5. 向量可用、重排不可用时采用 `95 × 非负余弦相关性 + 0.05 × 本地分数`；向量也不可用时保留原本地分数。未进入语义候选池的项目仅保留 5% 本地分数，仍可在完整列表中浏览。

分数是当前版本的推荐相关性，不是录取概率，也不保证不同算法模式之间可直接比较。原有 `factors` 保留可验证的标签匹配依据；它们不是混合总分的完整分解。导师名额仍通过双选模块显示和校验，未作为模型分数加减项。

匹配接口支持 `limit` 与 `offset`；`total` 是分页前的可见候选数。前端默认遵循后端推荐顺序，每页展示 20 条；搜索／学院筛选作用于完整已加载列表。同分顺序稳定，但画像、候选集合或降级状态变化时，新请求可能产生不同顺序，接口不提供跨请求快照保证。

## 缓存、隐私与降级

- 缓存以租户、模型／算法版本及清洗后内容的 SHA-256 标识；内容改变立即使用新缓存键。重复学术文本可在同一租户内复用向量，不跨租户复用。
- 向量默认保留 30 天，重排结果保留 900 秒。过期条目在该租户成功排序时清理；这些值由 `RANKING_EMBEDDING_TTL_DAYS`、`RANKING_CACHE_TTL_SECONDS` 控制。
- 缓存只保存向量、分数、指纹及有效期，不保存原始文本、API Key 或聊天内容。排序不扣除聊天额度。
- 学术字段采用白名单；不发送独立的姓名、账号、学工号、联系方式、成绩及院校管理字段；文本会去除已知本人身份信息、邮箱、URL 和常见电话号码，并限制为 1800 UTF-8 字节。此规则不能保证发现自由文本里的所有第三人信息；避免在学术描述中填入无关个人信息。
- 外部调用共享默认 15 秒预算，单次网络操作超时不超过 10 秒；预算检查覆盖批次及读取，属于尽力限制，并非操作系统级强制截止。单进程同时最多执行 2 个外部排序任务。失败后 30 秒内使用本地排序，无自动重试风暴。
- HTTP 错误、超时、畸形响应、维度错误、非有限数值、重复索引及缓存数据库错误都有降级保护；数据库缓存操作使用保存点，避免破坏外层业务事务。日志只记录固定原因码。
- `RANKING_ENABLED=false` 可关闭外部排序；接口中的 `ranking_mode` 提供 `local`、`semantic` 或 `hybrid` 诊断状态，用户页面不展示算法或服务降级说明。

## 验证与适用范围

最终回归结果：后端 105 项、前端 14 项通过；TypeScript 检查与前端生产构建通过。后端测试也在实际 Python 3.13 API 容器中连接独立 PostgreSQL 测试库全部通过。容器内真实 API 三个合成样例均通过，冷请求约 1.4–3.1 秒、缓存约 2–3 毫秒。HTTP 验证：首页、数据库健康检查、管理员登录与认证用户读取均返回 200；未登录访问匹配接口返回 401。运行数据库迁移版本为 `20260917_0015`。

已验证 PostgreSQL 完整迁移、1024 维向量读写／余弦查询、跨会话缓存、租户隔离、缓存过期／内容变更、限流／超时降级、权限前置过滤与分页。真实 API 的三个中文查询对英文 NLP、医学视觉、海洋生态文档的 Top-1 均符合预期，冷请求约 1.3–1.8 秒，内存数据库缓存请求约 2 毫秒。它们是小规模合成冒烟样本，不能代表真实推荐质量或生产数据库延迟。

当前实现是有界同步候选排序，不是全库 ANN 检索：候选超过 200 时，本地召回可能遗漏仅有语义关联的项目。部署规模扩大后需要离线全量建索引、召回评估及异步更新；当前接口仍会加载完整可见列表，因此也不承诺大规模用户库的内存／延迟指标。默认权重是可解释的初始规则，尚未用真实人工标注数据训练或调优。

官方接口依据：[Embedding](https://api-docs.siliconflow.cn/docs/api/embeddings-post)、[Rerank](https://api-docs.siliconflow.cn/docs/api/rerank-post)。
